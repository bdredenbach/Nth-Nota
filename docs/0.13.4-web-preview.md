# Nth Nota 0.13.4 — iPhone web preview

The web deployment builds the complete browser app, including all six pinned browser libraries, and publishes `dist/` with `index.html` at the website root. Relative assets, manifest identity, start URL and service worker scope remain inside `/Nth-Nota/`.

## One-time GitHub setup

In [repository Pages settings](https://github.com/bdredenbach/Nth-Nota/settings/pages), select **GitHub Actions** under **Build and deployment → Source**. The existing **Nth Nota web preview** workflow builds, tests and deploys the app; no suggested starter workflow is needed. Run it from Actions, or re-run its failed deployment job after enabling Pages. Subsequent app pushes to `main` publish automatically after the web checks pass.

The expected address is https://bdredenbach.github.io/Nth-Nota/. It becomes available after GitHub Pages is enabled and the deployment succeeds.

## Testing on iPhone

Open the web address in Safari. Use Share → Add to Home Screen, leave **Open as Web App** enabled if shown, then tap Add. Open the new Nth Nota icon and let the initial offline preparation finish. Install Nth Nota in the navigation menu shows whether the app files are Prepared.

Notes are stored separately in each browser or installed web app. Use Backup & restore to keep a copy or move work between devices. Device-specific tools show their availability in the app; the web preview does not include Android's native services.

## Verification

The Pages build checks JavaScript, prepares all pinned vendor files, and runs an iPhone-sized browser smoke test in Chromium and WebKit. It checks the deployed project path, installation metadata, complete dependencies, service worker scope and offline preparation, note saving, online reload, and offline launch with the saved note. WebKit automation is not a physical iPhone test.

The offline check stops the actual origin server and verifies that a browser without the cached app cannot connect, while the controlled app reloads through its service worker. Chromium also uses network offline emulation. WebKit uses the stopped-origin check because [Playwright’s WebKit offline emulation rejects service-worker navigation](https://github.com/microsoft/playwright/issues/42775). This does not simulate every hardware network condition.
