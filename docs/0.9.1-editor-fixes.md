# Nth Nota 0.9.1 — editor fixes

The recording exposed three related editor issues: the Ink and Handwrite ribbons selected their storage type instead of their actual input mode, touch taps retained hover decoration, and handwriting conversion failed before recognition started.

## Changes

- Select Ink for cursive or pressure ink, Handwrite for handwriting-to-text, Sketch for sketching, and Type for ordinary notes. Update the selected tool when changing drawing modes or undoing and redoing that change. Structured creative modes do not claim to be Type.
- Restrict hover decoration to devices with a fine pointer and genuine hover support. Keep selected controls and keyboard focus indications.
- Supply an explicit empty pre-context when building the ML Kit recognition context. SDK 19.0.0 otherwise throws `IllegalStateException: Missing required properties: preContext` before reading strokes. The existing writing area, local recognition, model downloads, cancellation, and saved strokes remain intact.

## Validation

The pre-context failure was reproduced locally against the actual Google ML Kit 19.0.0 artifact, and the corrected builder completed. Native tests exercise the packaged SDK rather than a recognition fixture. Browser coverage checks tool selection, mode changes and undo/redo, touch hover behavior, keyboard focus, and a failed handwriting conversion that preserves strokes and allows retry.

Handwriting accuracy and the complete SDK inference flow still require testing on a physical device. No Worker update is needed for these fixes.
